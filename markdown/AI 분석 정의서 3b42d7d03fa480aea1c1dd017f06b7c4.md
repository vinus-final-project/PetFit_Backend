# AI 분석 정의서

# 문서 개요

본 문서는 Pet Fit 서비스의 AI 분석 기준을 정의한다.

AI는 사용자가 촬영한 **생활공간 영상**과 선택한 **반려동물 그룹(animalGroup)** 을 기반으로 객체를 탐지하고, 반려동물 그룹의 생활 특성을 반영하여 환경을 분석한다.

분석 결과는 **위험 요소별 마킹 이미지**와 함께 **Pet Fit Score**, 위험 요소 및 환경 개선 추천으로 제공된다.

본 문서는 각 단계의 **판정 기준과 계산 규칙**을 정의한다. 구성 요소와 실행 순서는 AI 설계서를 따른다.

---

# AI 입력 데이터

| 입력 항목 | 설명 |
| --- | --- |
| animalGroup | 사용자가 선택한 반려동물 그룹 |
| spaceType | 사용자가 선택한 공간 종류 |
| Video | 생활공간 촬영 영상 |

영상 해상도는 분석 입력으로 사용하지 않는다. Bounding Box 좌표를 정규화하므로 해상도와 무관하게 처리한다.

영상 길이는 프레임 추출 장수를 결정하는 데 사용하며, `capture_duration` 으로 저장한다.

# 공간 종류

분석 대상 공간을 사용자가 선택한다. 공간에 따라 평가하는 분석 항목이 달라진다.

| 코드 | 이름 |
| --- | --- |
| living_room | 거실 |
| bedroom | 침실 |
| kitchen | 주방 |
| balcony | 베란다 |

## 공간별 적용 항목

| 분석 항목 | 유형 | 거실 | 침실 | 주방 | 베란다 |
| --- | --- | --- | --- | --- | --- |
| 전선 노출 | 탐지 | ● | ● | ● | ● |
| 계단 위험 | 탐지 | ● | ● | ● | ● |
| 창문 안전 | 탐지 | ● | ● | ● | ● |
| 활동 공간 | 점유율 | ● | ● | — | — |
| 미끄럼 위험 | 부재 | ● | ● | — | — |
| 휴식 공간 | 부재 | ● | ● | — | — |
| 수직 공간 | 부재 | ● | ● | — | — |
| 급식·급수 환경 | 부재 | ● | — | ● | — |
| 숨을 공간 | 산출 불가 | — | — | — | — |

`—` 항목은 **가중치 합에서 제외한다.** 산출 불가 항목과 동일하게 처리한다.

---

## 항목 유형

| 유형 | 감점 조건 | 공간별 구분 |
| --- | --- | --- |
| 탐지형 | 객체가 **있으면** 감점 | 불필요 |
| 부재형 | 객체가 **없으면** 감점 | 필요 |
| 점유율형 | 공간 점유율로 감점 | 필요 |

탐지형은 해당 공간에 객체가 없으면 감점률이 0이므로 전 공간에 적용해도 결과가 왜곡되지 않는다. 베란다에 계단이 없으면 감점이 발생하지 않는다.

부재형은 다르다. **객체가 없는 것이 정상인 공간에서 감점이 발생한다.**

---

## 제외 근거

| 조합 | 근거 |
| --- | --- |
| 급식·급수 × 침실 | 침실에 급식기·급수기를 두지 않는 것이 일반적이다. |
| 휴식 공간 × 주방·베란다 | 주방과 베란다에 반려동물 침대를 두지 않는다. |
| 수직 공간 × 주방·베란다 | 캣타워를 두는 공간이 아니다. |
| 미끄럼 위험 × 주방 | 위생상 카펫을 깔지 않는다. 카펫 유무로 판정하는 것이 부적절하다. |
| 활동 공간 × 주방·베란다 | 좁은 것이 정상이므로 점유율 감점이 부당하다. |

공간 구분이 없으면 침실만 촬영해도 "급수기가 없습니다"로 감점된다. 정상적인 공간이 낮은 점수를 받으면 사용자가 결과를 신뢰하지 않는다.

> ※ 베란다는 탐지형 3개만 평가한다. 창문 안전이 실질적 판정 항목이며, 고양이 추락 위험을 확인하는 것이 베란다 촬영의 주 목적이다.

# AI 분석 단계

| 단계 | 설명 | 본 문서에서 정의하는 기준 |
| --- | --- | --- |
| 1 | 영상 입력 | — |
| 2 | 프레임 추출 | 추출 간격, 장수 |
| 3 | 객체 탐지 | 탐지 대상 12종 |
| 4 | 활동 공간 점유율 산출 | 합집합 면적, 중앙값 |
| 5 | 객체 추적 | 통합 결과 산출 방식 |
| 6 | 탐지 신뢰 기준 적용 | confidence, 탐지 프레임 수 |
| 7 | 객체명 변환 | 클래스 코드 ↔ 한글명 매핑 |
| 8 | 위험도 판정 | 객체 × animalGroup → risk_level |
| 9 | 대표 프레임 선정 | 분석 대표 · 객체 대표 선정 기준 |
| 10 | 위험 객체 마킹 | 색상 매핑, 생성 규칙 |
| 11 | Pet Fit Score 산출 | 감점률, 가중치, 계산식 |
| 12 | 환경 분석 · 개선 추천 생성 | 그룹별 분석 기준 |

단계 4가 5보다 앞서는 이유는 점유율이 **프레임 단위 지표**이기 때문이다. 객체 추적으로 통합하면 프레임별 정보가 사라져 산출할 수 없다.

단계 12는 LLM/VLM이 한 번의 호출로 위험 요소·분석·추천을 함께 생성한다.

# 프레임 추출

AI는 촬영된 영상에서 일정 간격으로 프레임을 추출하여 분석한다.

### 목적

- 공간 전체 확보
- 다양한 시점 확보
- 객체 누락 최소화

### 추출 기준

```
목표 장수 = clamp(영상 길이(초) × 3, 15, 30)
추출 간격 = 영상 길이 / 목표 장수
```

| 항목 | 값 |
| --- | --- |
| 기준 추출률 | 초당 3프레임 |
| 최소 추출 프레임 | 15장 |
| 최대 추출 프레임 | 30장 |
| 추출 방식 | 영상 전체 구간에서 균등 간격 |

장수를 먼저 정하고 간격을 역산한다. 허용 촬영 길이가 3~30초로 넓어 고정 간격만 사용하면 장수가 범위를 벗어난다.

### 영상 길이별 추출 프레임 수

| 영상 길이 | 3fps 적용 시 | 실제 추출 | 간격 |
| --- | --- | --- | --- |
| 3초 | 9장 | **15장** | 0.20초 |
| 5초 | 15장 | 15장 | 0.33초 |
| 8초 | 24장 | 24장 | 0.33초 |
| 10초 | 30장 | 30장 | 0.33초 |
| 20초 | 60장 | **30장** | 0.67초 |
| 30초 | 90장 | **30장** | 1.00초 |

짧은 영상은 간격을 좁혀 최소 장수를 확보하고, 긴 영상은 간격을 넓혀 연산량을 제한한다.

| 구간 | 동작 |
| --- | --- |
| 3 ~ 5초 | 간격을 좁혀 15장 확보 |
| 5 ~ 10초 | 초당 3프레임 그대로 적용 |
| 10 ~ 30초 | 간격을 넓혀 30장으로 제한 |

> ※ 권장 촬영 길이는 5~10초이며, 이 구간에서 기준 추출률이 그대로 적용된다.
> 
> ※ 허용 범위는 3~30초이다. 촬영 가이드는 권장 구간을 안내한다.

원본 영상이 30FPS인 경우 10초 영상은 300프레임이지만, 전 프레임을 분석하면 인접 프레임이 거의 동일하여 연산만 증가하고 정보량은 늘지 않는다.

공간을 천천히 이동하며 촬영하는 사용 방식을 고려할 때 초당 3프레임이면 시점 변화를 충분히 담을 수 있다.

> ※ 추출 간격은 성능평가를 통해 조정한다.

# 객체 코드 · 명칭 매핑

YOLO는 영문 클래스 코드를 출력하고, 데이터베이스와 API는 한글 객체명을 사용한다.

변환은 백엔드에서 수행하며, 매핑 기준은 위 `클래스 코드` · `객체` 열을 따른다.

| 계층 | 사용 값 | 예시 |
| --- | --- | --- |
| YOLO 출력 | 클래스 코드 (영문) | `cable` |
| 백엔드 변환 | 매핑표 조회 | `cable` → `전선` |
| DB 저장 | 한글 객체명 | `전선` |
| API 응답 | 한글 객체명 | `전선` |

### 규칙

| 항목 | 내용 |
| --- | --- |
| 클래스 코드 | snake_case 영문만 사용한다. |
| 매핑 누락 | 매핑표에 없는 코드는 저장하지 않고 무시한다. |
| 코드 변경 | 클래스 코드 변경 시 학습 데이터셋과 매핑표를 함께 갱신한다. |

> ※ 다국어 지원 시 DB에 클래스 코드를 저장하고 표시 시점에 변환하는 구조로 전환한다.

# 위험도 판정 규칙

`risk_level` 은 YOLO가 산출하지 않는다. 탐지된 객체와 반려동물 그룹의 조합으로 백엔드가 판정한다.

```
risk_level = max(중요도 유래 등급, 객체별 최소 위험도)
```

## 1단계 — 중요도 유래 등급

반려동물 그룹별 분석 기준의 중요도를 등급으로 변환한다.

| 중요도 | 등급 |
| --- | --- |
| ●● | HIGH |
| ● | MEDIUM |
| ○ | LOW |

## 2단계 — 객체별 최소 위험도

물리적 위해가 **반려동물 종류와 무관한** 객체는 하한을 둔다.

| 객체 | 최소 위험도 | 사유 |
| --- | --- | --- |
| 전선 | **HIGH** | 감전 위험은 종에 무관하다. 고양이는 씹는 습성으로 오히려 위험이 크다. |

다른 객체는 하한을 두지 않는다.

### 하한을 두는 기준

| 조건 | 예시 |
| --- | --- |
| 종에 무관하게 위해가 발생한다 | 전선 (감전) |
| 종에 따라 위험이 달라진다 | 창문 (고양이 추락), 계단 (대형견 관절) |

## 판정 결과

| 객체 | 소형견 | 중·대형견 | 고양이 |
| --- | --- | --- | --- |
| 전선 | HIGH | HIGH | **HIGH** |
| 계단 | MEDIUM | HIGH | LOW |
| 창문 | LOW | LOW | HIGH |
| 그 외 전체 | SAFE | SAFE | SAFE |

### 전선에 하한이 필요한 이유

고양이의 전선 중요도는 `●` 이며, 하한이 없으면 `MEDIUM`(노란색)으로 표시된다.

중요도가 낮은 이유는 창문·수직 공간·숨을 공간이 `●●` 라 **상대적으로 밀렸기 때문**이지 전선이 안전해서가 아니다.

색상은 사용자에게 **절대적 위험도**로 읽힌다. 노란색을 보고 전선 정리를 미루면 실제 사고로 이어질 수 있다.

> ※ 하한은 색상 표시에만 적용된다. 점수 계산의 가중치는 중요도를 그대로 사용하므로 **점수는 변하지 않는다.**

### risk_level의 용도

| 용도 | 사용 여부 |
| --- | --- |
| 위험 객체 마킹 색상 결정 | ● 사용 |
| Pet Fit Score 산출 | ○ **사용하지 않음** |

> ※ `risk_level` 은 이미 그룹별 중요도를 반영한 값이다.
> 
> ※ 점수 계산식의 가중치 `w` 도 동일한 중요도를 사용하므로, `risk_level` 을 감점률에 반영하면 중요도가 이중으로 적용된다. 점수 산출에는 사용하지 않는다.

# 객체 추적(Object Tracking)

영상의 연속 프레임에서 동일 객체를 추적한다.

### 목적

- 중복 탐지 제거
- 객체 위치 안정화
- 분석 정확도 향상
- 오탐 제거

### 통합 결과

| 항목 | 산출 방식 |
| --- | --- |
| confidence | 탐지된 프레임 중 **최댓값** |
| frame_number | confidence가 가장 높은 프레임. 동점이면 Bounding Box 면적이 큰 프레임, 그래도 동점이면 프레임 번호가 작은 프레임 |
| detection_frame_count | 해당 객체가 탐지된 프레임 수 |

`frame_number` 가 곧 해당 객체의 **객체 대표 프레임**이다. 대표 프레임 선정 단계에서 다시 계산하지 않는다.

# 탐지 신뢰 기준

탐지 결과를 그대로 사용하지 않는다. 두 단계로 검증한다.

| 단계 | 기준 |
| --- | --- |
| 1. 프레임 단위 탐지 | `confidence ≥ 0.25` |
| 2. 객체 채택 (추적 통합 후) | `최고 confidence ≥ 0.40` **그리고** `detection_frame_count ≥ 2` |

2단계를 통과하지 못한 객체는 **저장하지 않고 폐기한다.** 점수 산출과 마킹 어디에도 사용하지 않는다.

## 탐지 프레임 수를 함께 사용하는 이유

confidence만으로는 오탐을 걸러내기 어렵다.

전선처럼 가늘고 배경과 유사한 객체는 실제로 존재해도 confidence가 낮게 나온다. 임계값을 높이면 실재하는 위험 요소를 놓치고, 낮추면 오탐이 점수에 반영된다.

반면 **탐지 프레임 수는 오탐과 실재를 잘 구분한다.**

| 상황 | 판정 |
| --- | --- |
| 30프레임 중 1프레임에서만 탐지 | 오탐 가능성이 높다 |
| 30프레임 중 12프레임에서 탐지 | 실재할 가능성이 높다 |

객체 추적 결과에 이미 포함된 정보이므로 추가 연산이 발생하지 않는다.

## 오탐이 점수에 미치는 영향

전선 노출은 소형견 기준 가중치 `●●` = 3이며, 안전성 가중치 합은 8이다.

전선 오탐 1건이 안전성 점수를 **37.5포인트** 낮추고, 종합 점수를 **15포인트** 낮춘다.

규칙 기반 산출의 재현성은 입력이 정확할 때만 의미가 있으므로, 탐지 단계의 신뢰 기준이 점수 신뢰도의 전제가 된다.

> ※ 임계값은 성능평가를 통해 클래스별로 조정한다. 특히 `cable` 은 별도 확인이 필요하다.

# 대표 프레임 선정

대표 프레임은 두 종류를 선정한다.

| 구분 | 범위 | 용도 |
| --- | --- | --- |
| 분석 대표 프레임 | 분석당 1장 | 목록·썸네일 표시 |
| 객체 대표 프레임 | 위험 객체당 1장 | 위험 요소 마킹 이미지 |

---

## 분석 대표 프레임

목록 화면과 결과 화면 상단에 사용할 썸네일이다.

### 선정 기준

우선순위 순으로 적용한다. 앞 기준에서 동점이면 다음 기준으로 넘어간다.

| 순위 | 기준 | 방향 |
| --- | --- | --- |
| 1 | 포함된 주요 객체의 **종류 수** | 많을수록 우선 |
| 2 | 해당 프레임 탐지 객체의 **평균 confidence** | 높을수록 우선 |
| 3 | **프레임 번호** | 작을수록 우선 |

3순위까지 적용하면 항상 하나의 프레임이 결정된다.

> ※ "객체 가림이 적은 프레임", "선명도가 높은 프레임" 은 측정 방법이 정의되지 않아 선정 기준에서 제외한다. 측정 가능한 기준만 사용한다.

### 주요 객체의 정의

**감점률 산출 규칙의 판정 근거로 사용되는 객체**를 주요 객체로 본다.

| 주요 객체 | 소파, 침대, 반려동물 침대, 창문, 전선, 계단, 카펫, 급식기, 급수기, 캣타워 |
| --- | --- |
| 주요 객체 아님 | 의자, 테이블 |

의자와 테이블은 점유율 계산에만 사용되므로 대표 프레임 선정 기준에 포함하지 않는다.

---

## 객체 대표 프레임

위험 객체마다 **해당 객체가 가장 잘 보이는 프레임**을 개별 선정한다.

### 선정 기준

우선순위 순으로 적용한다.

| 순위 | 기준 | 방향 |
| --- | --- | --- |
| 1 | 해당 객체의 **confidence** | 높을수록 우선 |
| 2 | 해당 객체의 **Bounding Box 면적** | 클수록 우선 |
| 3 | **프레임 번호** | 작을수록 우선 |

이는 객체 추적이 산출하는 `frame_number` 와 동일한 값이다. 객체 추적 단계에서 이미 결정되므로 별도로 다시 계산하지 않는다.

`confidence` 를 1순위로 두는 이유는, 면적이 커도 흐릿하게 잡힌 프레임보다 선명하게 인식된 프레임이 마킹 이미지로 적합하기 때문이다.

### 선정 이유

공간을 이동하며 촬영하므로 위험 요소가 서로 다른 장면에 나타난다.

한 장의 프레임에 모든 위험 요소가 담기지 않으며, 특정 프레임만 사용하면 **다른 장면의 위험 요소를 표시할 수 없다.**

객체별로 프레임을 선정하면 모든 위험 요소를 누락 없이 시각화할 수 있다.

| 예시 | 객체 대표 프레임 |
| --- | --- |
| 전선 | 3번 |
| 창문 | 18번 |
| 계단 | 25번 |

> ※ Bounding Box 좌표는 해당 객체의 **객체 대표 프레임** 기준 정규화 좌표이다.

---

# 위험 객체 마킹

위험 객체마다 **객체 대표 프레임에 Bounding Box를 그린 이미지를 개별 생성한다.**

| risk_level | 의미 | 마킹 이미지 |
| --- | --- | --- |
| HIGH | 위험도 높음 | 빨간색 Bounding Box |
| MEDIUM | 위험도 보통 | 노란색 Bounding Box |
| LOW | 위험도 낮음 | 초록색 Bounding Box |
| SAFE | 위험 요소 아님 | **생성하지 않음** |

### 생성 규칙

| 항목 | 내용 |
| --- | --- |
| 생성 대상 | `risk_level` 이 HIGH · MEDIUM · LOW인 객체 |
| 생성 단위 | 객체 1개당 이미지 1장 |
| 배경 프레임 | 해당 객체의 객체 대표 프레임 |
| 표시 내용 | 해당 객체의 Bounding Box 1개만 표시 |

한 이미지에 여러 객체를 표시하지 않는다. 위험 요소를 하나씩 확인할 수 있도록 분리한다.

`SAFE` 객체는 위험 요소가 아니므로 마킹 이미지를 생성하지 않는다.

### 결과 화면 구성

**소형견** 기준 예시이다. 색상은 반려동물 그룹에 따라 달라진다.

```
분석 대표 프레임 (썸네일)
        │
        ▼
위험 요소 3건
   ├─ 전선   [마킹 이미지]  빨간색 (HIGH)
   ├─ 계단   [마킹 이미지]  노란색 (MEDIUM)
   └─ 창문   [마킹 이미지]  초록색 (LOW)
```

동일한 객체라도 그룹이 다르면 색상이 달라진다.

| 객체 | 소형견 | 고양이 |
| --- | --- | --- |
| 전선 | 빨간색 | 빨간색 (하한 적용) |
| 계단 | 노란색 | 초록색 |
| 창문 | 초록색 | 빨간색 |

---

동일 입력에 항상 동일한 순서로 반환하기 위해 정렬 기준을 명시한다.

### 탐지 객체 목록

| 순위 | 기준 | 방향 |
| --- | --- | --- |
| 1 | risk_level | HIGH → MEDIUM → LOW → SAFE |
| 2 | confidence | 높을수록 우선 |
| 3 | object_name | 가나다순 |

| 순위 | 기준 |
| --- | --- |

### 마킹 이미지 목록

탐지 객체 목록에서 `SAFE` 를 제외한 순서를 그대로 따른다.

### 개선 추천 목록

`priority` 오름차순. `UNIQUE (analysis_id, priority)` 제약으로 동점이 발생하지 않는다.

## 항목별 감점률 산출 규칙

각 분석 항목은 탐지 결과에 따라 감점률 `p` (0.0 ~ 1.0)를 산출한다.

`p = 0.0` 은 문제 없음, `p = 1.0` 은 최대 감점을 의미한다.

감점률은 **반려동물 그룹과 무관하게** 산출한다. 그룹별 차이는 가중치 `w` 로만 반영한다.

| 분석 항목 | 판정 근거 | 감점률(p) |
| --- | --- | --- |
| 활동 공간 | 프레임별 점유율 중앙값 | 아래 표 참조 |
| 전선 노출 | 전선 | 탐지 1.0 / 미탐지 0.0 |
| 계단 위험 | 계단 | 탐지 1.0 / 미탐지 0.0 |
| 창문 안전 | 창문 | 탐지 1.0 / 미탐지 0.0 |
| 미끄럼 위험 | 카펫 | 탐지 0.0 / 미탐지 0.5 |
| 수직 공간 | 캣타워 | 탐지 0.0 / 미탐지 1.0 |
| 휴식 공간 | 반려동물 침대, 소파, 침대 | 반려동물 침대 탐지 0.0 / 소파·침대만 탐지 0.4 / 미탐지 1.0 |
| 급식·급수 환경 | 급식기, 급수기 | 둘 다 탐지 0.0 / 하나만 탐지 0.5 / 미탐지 1.0 |
| 숨을 공간 | — | **산출 불가** |

> ※ 위험 항목(전선·계단·창문)은 Bounding Box만으로 위험의 정도를 판별할 수 없으므로 탐지 여부만 사용한다.
> 
> ※ `risk_level` 을 감점률에 반영하지 않는다. 중요도가 이중 적용된다.

### 활동 공간 점유율

점유율은 **프레임 단위 지표**이다. 객체마다 대표 프레임이 다르므로 객체 단위로 산출할 수 없다.

#### 산출 절차

| 단계 | 내용 |
| --- | --- |
| 1 | 추출된 각 프레임에서 탐지 객체의 Bounding Box **합집합 면적**을 구한다. |
| 2 | 합집합 면적을 프레임 면적으로 나눈다. |
| 3 | 전체 프레임의 점유율 중 **중앙값**을 최종 점유율로 사용한다. |

```
프레임별 점유율 = 합집합 면적 / 프레임 면적
최종 점유율     = median(프레임별 점유율)
```

#### 합집합 면적을 사용하는 이유

Bounding Box는 서로 겹친다. 테이블 아래의 의자, 소파 앞의 테이블이 대표적이다.

단순히 면적을 더하면 겹친 영역이 **중복 계산되어 점유율이 1.0을 초과할 수 있다.** 여유 있는 공간이 "활동 공간 부족"으로 잘못 판정된다.

| 방식 | 테이블(0.20) + 의자(0.06, 테이블 아래) |
| --- | --- |
| 면적 합 | 0.26 |
| 합집합 | 0.20 |

#### 합집합 면적 산출 방법

**좌표 압축(Coordinate Compression)** 으로 계산한다. 근사가 아니라 정확값을 산출한다.

| 순서 | 처리 |
| --- | --- |
| 1 | 모든 Bounding Box의 x 좌표(`x`, `x + width`)를 모아 중복을 제거하고 정렬한다 |
| 2 | y 좌표(`y`, `y + height`)도 동일하게 처리한다 |
| 3 | 두 좌표 목록이 만드는 각 셀의 중심이 하나 이상의 Bounding Box 안에 있는지 확인한다 |
| 4 | 포함된 셀의 실제 면적을 모두 더한다 |

```
셀 면적 = (x[i+1] − x[i]) × (y[j+1] − y[j])
점유율  = Σ(포함된 셀 면적)
```

#### 고정 격자를 사용하지 않는 이유

박스 경계에서만 분할하면 **각 셀은 전부 덮이거나 전부 덮이지 않는다.** 부분 겹침이 발생하지 않으므로 근사 오차가 없다.

고정 격자(예: 100 × 100)는 셀이 박스 경계를 가로질러 오차가 남는다. 판정 기준에 따라 결과도 달라진다.

| 방식 | 정확도 | 셀 수 | 튜닝 파라미터 |
| --- | --- | --- | --- |
| 고정 격자 100 × 100 | ±2% 내외 | 10,000 | 격자 해상도 |
| **좌표 압축** | **정확** | **최대 529** | **없음** |

탐지 객체가 최대 12종이므로 좌표는 각 축당 최대 24개, 셀은 최대 23 × 23 = 529개이다. 고정 격자보다 적다.

#### 오차가 점수를 바꾼다

점유율 임계값이 `0.40 / 0.60 / 0.75` 로 고정되어 있다.

```
실제 0.395  →  격자 오차 +2%  →  0.403  →  감점 0.0 → 0.4
```

측정 오차가 감점률을 뒤집는다. 규칙 기반 산출의 재현성을 확보하려면 면적 계산에 오차 항이 없어야 한다.

#### 중앙값 산출 규칙

프레임 수가 15~30장이므로 짝수인 경우가 발생한다.

| 프레임 수 | 중앙값 |
| --- | --- |
| 홀수 | 가운데 값 |
| **짝수** | **가운데 두 값의 산술 평균** |

24프레임이면 정렬 후 12번째와 13번째 값의 평균을 사용한다.

방식을 명시하지 않으면 하위값·상위값·평균이 각각 다른 감점률을 만든다. 임계값이 `0.40` 으로 고정되어 있어 경계 근처에서 결과가 갈린다.

#### 수치 비교 규칙

점유율과 감점률은 부동소수점 연산 결과이므로 임계값과 정확히 일치하지 않는다.

```
0.05 + 0.35 = 0.39999999999999997   →  "0.40 이하" 판정이 계산 순서에 따라 달라진다
```

| 항목 | 규칙 |
| --- | --- |
| 비교 대상 | 점유율, confidence |
| 처리 | **비교 전 소수점 4자리에서 Round Half Up** |
| 근거 | Bounding Box 좌표가 `DECIMAL(5,4)` 이므로 자릿수를 맞춘다 |

`0.39999999999999997` 은 `0.4000` 으로 정규화된 뒤 임계값과 비교한다.

#### 중앙값을 사용하는 이유

촬영 중 일부 프레임은 벽면만 담기거나(점유율 0에 근접) 가구를 근접 촬영한다(1.0에 근접).

평균은 이러한 이상치에 영향을 받는다. 중앙값은 공간의 일반적인 상태를 반영한다.

#### 감점률

| 점유율 | 감점률(p) |
| --- | --- |
| 0.40 이하 | 0.0 |
| 0.40 초과 0.60 이하 | 0.4 |
| 0.60 초과 0.75 이하 | 0.7 |
| 0.75 초과 | 1.0 |

### 가중치 합에서 제외하는 항목

두 경우에 항목을 가중치 합에서 제외한다. 감점 0으로 처리하지 않는다.

| 사유 | 대상 |
| --- | --- |
| 산출 불가 | `숨을 공간` — 판정할 탐지 객체가 정의되지 않았다 |
| **공간 미적용** | 공간별 적용 항목 표에서 `—` 인 항목 |

감점 0으로 처리하면 해당 항목이 만점인 것처럼 계산되어 점수가 부풀려진다. 제외해야 나머지 항목만으로 정확히 평가된다.

`분모(Σw)`와 `분자(Σw·p)` 양쪽에서 함께 빠진다.

> ※ 탐지 객체에 은신처(박스·터널·펫하우스)가 추가되면 본 항목을 산출 대상에 포함한다.
> 
> ※ 고양이는 `숨을 공간` 이 매우 중요(●●) 항목이므로, 현재 휴식환경 점수는 `휴식 공간` 하나로만 산출된다.

## 점수 계산식

### 평가 항목별 점수

평가 항목 `C` 에 속한 산출 가능한 분석 항목 `i` 에 대하여,

```
score(C) = 100 × ( 1 − Σ(w_i × p_i) / Σ(w_i) )
```

- `w_i` : 반려동물 그룹별 중요도 가중치
- `p_i` : 항목별 감점률
- 결과는 0 이상 100 이하의 정수로 반올림한다.
- 산출 가능한 항목이 하나도 없으면 해당 평가 항목은 100으로 처리한다.

### 반올림 규칙

| 항목 | 규칙 |
| --- | --- |
| 방식 | **Round Half Up** — 0.5는 올림한다 |
| 적용 시점 | 평가 항목별 점수와 종합 점수에 각각 적용한다 |
| 중간 계산 | 반올림하지 않고 실수로 유지한다 |

`49.5` 는 `50` 이 된다.

언어와 라이브러리에 따라 기본 반올림 방식이 다르다. Python의 `round()` 는 은행가 반올림(Round Half to Even)이라 `round(0.5) = 0`, `round(1.5) = 2` 가 된다. 규칙을 명시하지 않으면 **동일 입력에 서로 다른 점수가 나온다.**

결정성을 보장하려면 구현에서 반올림 방식을 명시적으로 지정해야 한다.

### 종합 점수

```
total = round( safety × 0.40
             + activity × 0.25
             + rest × 0.20
             + environment × 0.15 )
```

## 계산 예시 (소형견 · 거실)

### 탐지 결과

| 탐지 객체 | 비고 |
| --- | --- |
| 전선 | |
| 창문 | |
| 카펫 | |
| 소파 | |
| 급수기 | |

- 캣타워 미탐지
- 계단 미탐지
- 급식기 미탐지
- 반려동물 침대 미탐지
- 프레임별 점유율 중앙값 : 0.35

### 안전성

| 분석 항목 | 중요도 | w | p | w × p |
| --- | --- | --- | --- | --- |
| 전선 노출 | ●● | 3 | 1.0 | 3.0 |
| 미끄럼 위험 | ● | 2 | 0.0 | 0.0 |
| 계단 위험 | ● | 2 | 0.0 | 0.0 |
| 창문 안전 | ○ | 1 | 1.0 | 1.0 |
| **합계** |  | **8** |  | **4.0** |

`safety = 100 × (1 − 4.0 / 8) = 50`

### 활동성

| 분석 항목 | 중요도 | w | p | w × p |
| --- | --- | --- | --- | --- |
| 활동 공간 | ● | 2 | 0.0 | 0.0 |
| 수직 공간 | ○ | 1 | 1.0 | 1.0 |
| **합계** |  | **3** |  | **1.0** |

`activity = 100 × (1 − 1.0 / 3) = 66.67 → 67`

### 휴식환경

| 분석 항목 | 중요도 | w | p | w × p |
| --- | --- | --- | --- | --- |
| 휴식 공간 | ● | 2 | 0.4 | 0.8 |
| 숨을 공간 | ○ | — | 산출 불가 | 제외 |
| **합계** |  | **2** |  | **0.8** |

`rest = 100 × (1 − 0.8 / 2) = 60`

### 생활환경

| 분석 항목 | 중요도 | w | p | w × p |
| --- | --- | --- | --- | --- |
| 급식·급수 환경 | ● | 2 | 0.5 | 1.0 |
| **합계** |  | **2** |  | **1.0** |

`environment = 100 × (1 − 1.0 / 2) = 50`

### 종합

```
total = round(50 × 0.40 + 67 × 0.25 + 60 × 0.20 + 50 × 0.15)
      = round(20.00 + 16.75 + 12.00 + 7.50)
      = round(56.25)
      = 56
```

| 객체 | risk_level | 마킹 |
| --- | --- | --- |
| 전선 | HIGH | 빨간색 |
| 창문 | LOW | 초록색 |
| 카펫 | SAFE | 표시 안 함 |
| 소파 | SAFE | 표시 안 함 |
| 급수기 | SAFE | 표시 안 함 |

> ※ 위 `risk_level` 은 마킹에만 사용되며 점수 계산에는 관여하지 않는다.

## 공간별 점수 비교

동일한 탐지 결과를 공간만 바꿔 산출한 결과이다.

| 공간 | 안전성 | 활동성 | 휴식환경 | 생활환경 | **종합** |
| --- | --- | --- | --- | --- | --- |
| 거실 | 50 | 67 | 60 | 50 | **56** |
| 침실 | 50 | 67 | 60 | **100** | **64** |
| 베란다 | **33** | **100** | **100** | **100** | **73** |

### 침실

`급식·급수 환경` 이 제외되어 생활환경에 산출 가능한 항목이 없다. 해당 평가 항목은 **100** 으로 처리한다.

침실에 급수기가 없다고 감점하지 않으므로 종합 점수가 56 → 64로 오른다.

### 베란다

탐지형 3개(전선·계단·창문)만 평가한다. 미끄럼 위험까지 빠지므로 안전성 가중치 합이 8에서 6으로 줄고, 전선·창문 감점의 비중이 커져 33으로 낮아진다.

활동성·휴식환경·생활환경은 산출 항목이 없어 모두 100이 된다.

> ※ 공간마다 평가 대상이 다르므로 **서로 다른 공간의 점수를 직접 비교하지 않는다.** 결과 화면에 공간 종류를 함께 표시한다.
