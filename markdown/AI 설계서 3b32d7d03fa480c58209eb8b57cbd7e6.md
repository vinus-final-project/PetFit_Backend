# AI 설계서

# 문서 개요

본 문서는 Pet Fit 서비스의 AI 시스템 구조와 데이터 처리 과정을 정의한다.

AI 시스템은 **영상 기반 객체 탐지(Object Detection)**, **객체 추적(Object Tracking)**, **생성형 AI(LLM/VLM)** 를 결합하여 반려동물 그룹별 생활환경을 분석한다.

역할은 두 갈래로 나뉜다.

| 산출물 | 담당 | 방식 |
| --- | --- | --- |
| Pet Fit Score | Score Generator | 규칙 기반, 결정적 |
| 위험 요소 · 분석 · 개선 추천 | LLM / VLM | 생성형 |

본 문서는 **AI 파이프라인의 정본**이다. 구성 요소와 실행 순서는 본 문서를 기준으로 한다.

# AI 시스템 아키텍처

```
            ┌─────────────────────────────────┐
            │        React + Capacitor        │
            └────────────────┬────────────────┘
              Video + animalGroup + spaceType
                             ▼
            ┌─────────────────────────────────┐
            │          FastAPI Server         │
            └────────────────┬────────────────┘
                             ▼
   ╔═══════════════ 영상 처리 ═══════════════╗
   ║  1. Video Processor                     ║
   ║  2. Frame Extractor    (3fps, 15~30장)  ║
   ╚════════════════════╤════════════════════╝
                        ▼
   ╔═══════════════ 객체 인식 ═══════════════╗
   ║  3. Object Detection      (프레임 단위) ║
   ║  4. Occupancy Calculator  → 점유율      ║
   ║  5. Object Tracking       (객체 통합)   ║
   ║  6. Detection Filter      (오탐 제거)   ║
   ║  7. Object Name Mapper    (코드→한글)   ║
   ║  8. Risk Classifier       → risk_level  ║
   ╚════════════════════╤════════════════════╝
                        ▼
   ╔═══════════════ 시각화 ═════════════════╗
   ║  9. Representative Frame Selection      ║
   ║ 10. Risk Object Marking  (객체별 N장)   ║
   ╚════════════════════╤════════════════════╝
                        ▼
            ┌─────────────────────────────────┐
            │  11. Score Generator (Rule)     │──▶ petFitScore
            └────────────────┬────────────────┘
                             │
        객체 목록 + animalGroup + spaceType + petFitScore
              + 원본 프레임 이미지 (최대 4장)
                             ▼
            ┌─────────────────────────────────┐      riskFactors
            │  12. Environment Analysis       │──▶   analysis
            │          (LLM / VLM)            │      recommendations
            └────────────────┬────────────────┘
                             ▼
            ┌─────────────────────────────────┐
            │          JSON Response          │
            └─────────────────────────────────┘
```

> Score Generator는 객체 탐지·추적 결과만으로 점수를 산출한다. LLM 출력에 의존하지 않는다.
> 
> 산출된 점수는 LLM 입력으로 전달하여 점수와 서술 내용의 일관성을 확보한다.

# AI 처리 흐름

```
영상 업로드
    │
    ▼
 1. 영상 검증
    │
    ▼
 2. 프레임 추출              초당 3프레임 (15~30장)
    │
    ▼
 3. 객체 탐지                프레임별 Bounding Box
    │
    ├──────────────┐
    ▼              ▼
 4. 점유율 산출    5. 객체 추적
    (프레임별      (프레임 간 통합)
     중앙값)              │
    │                     ▼
    │              6. 탐지 신뢰 기준 적용
    │                 confidence ≥ 0.40
    │                 탐지 프레임 ≥ 2
    │                     │
    │                     ▼
    │              7. 객체명 변환
    │                 cable → 전선
    │                     │
    │                     ▼
    │              8. 위험도 판정
    │                 객체 × animalGroup → risk_level
    │                     │
    └──────────┬──────────┘
               ▼
 9. 대표 프레임 선정
    분석 대표 1장 + 위험 객체별 각 1장
               │
               ▼
10. 위험 객체 마킹
    위험 객체당 이미지 1장 (SAFE 제외)
               │
               ▼
11. Pet Fit Score 산출
    규칙 기반, 결정적
               │
               ▼
12. LLM/VLM 환경 분석
    점수와 원본 이미지를 입력으로 사용
               │
               ▼
    JSON 결과 반환
```

`4. 점유율 산출` 이 분기하는 이유는 **프레임 단위 지표**이기 때문이다. 객체 추적으로 통합하면 프레임별 정보가 사라져 계산할 수 없다.

실행 순서대로 나열한다.

| 10 | Risk Object Marking | 위험 객체별 마킹 이미지 생성 |
| 11 | Score Generator | Pet Fit Score 규칙 기반 산출 |
| 12 | Environment Analysis | 환경 분석·위험 요소·개선 추천 생성 |

| --- | --- | --- |
| Video Processor | 영상 파일 | 검증된 영상 |
| Frame Extractor | 영상 | 프레임 목록 |

| Object Name Mapper | 채택된 객체 목록 | 한글명이 부여된 객체 목록 |

| Representative Frame Selection | 프레임 목록, 객체 목록 | 분석 대표 프레임, 객체별 대표 프레임 |
| Risk Object Marking | 객체 대표 프레임, 객체 정보 | 객체별 마킹 이미지 |
| Score Generator | 객체 목록, occupancy_ratio, animalGroup, spaceType | petFitScore |
| Environment Analysis | 객체 목록, petFitScore, spaceType, occupancy_ratio, 이미지 | riskFactors, analysis, recommendations |

### 순서 제약

| 제약 | 이유 |
| --- | --- |
| Occupancy Calculator는 Object Tracking 이전 | 점유율은 프레임 단위 지표이므로 통합 전 데이터가 필요하다 |
| Risk Classifier는 Risk Object Marking 이전 | 마킹 색상이 risk_level로 결정된다 |
| Detection Filter는 Score Generator 이전 | 오탐이 점수에 반영되지 않아야 한다 |
| Score Generator는 Environment Analysis 이전 | 점수를 LLM 입력으로 전달한다 |

> ※ `Recommendation Generator` 는 별도 구성 요소로 두지 않는다. 환경 개선 추천은 `Environment Analysis` 가 위험 요소·분석 서술과 함께 한 번의 호출로 생성한다.

# Occupancy Calculator

## 목적

활동 공간 점유율을 산출한다. 활동성 점수의 입력이 된다.

### 산출 방식

```
프레임별 점유율 = Bounding Box 합집합 면적 / 프레임 면적
최종 점유율     = median(프레임별 점유율)
```

### 입력

- 프레임별 탐지 결과

### 출력

- occupancy_ratio

### 실행 위치

**Object Tracking 이전**에 실행한다. 점유율은 프레임 단위 지표이므로 객체 통합 후에는 산출할 수 없다.

면적은 단순 합이 아닌 **합집합**을 사용한다. 겹친 Bounding Box를 중복 계산하면 점유율이 1.0을 초과한다.

합집합은 **좌표 압축**으로 정확히 계산한다. 고정 격자 근사는 오차가 임계값 판정을 뒤집을 수 있어 사용하지 않는다.

> 상세 계산 방법은 AI 분석 정의서를 따른다.

# Object Tracking

## 목적

동일 객체를 프레임 간 추적하여 중복 탐지를 제거한다.

### 입력

- 프레임별 탐지 결과

### 출력

통합 객체 목록. 객체마다 아래 값을 산출한다.

| 항목 | 산출 방식 |
| --- | --- |
| confidence | 탐지된 프레임 중 **최댓값** |
| frame_number | confidence가 가장 높은 프레임 |
| detection_frame_count | 해당 객체가 탐지된 프레임 수 |

`detection_frame_count` 는 다음 단계의 오탐 판정 근거가 된다.

---

# Detection Filter

## 목적

오탐을 제거한다. 채택되지 않은 객체는 저장하지 않으며 점수와 마킹 어디에도 사용하지 않는다.

### 채택 기준

| 조건 | 값 |
| --- | --- |
| confidence | 0.40 이상 |
| detection_frame_count | 2 이상 |

### 두 조건을 함께 쓰는 이유

전선처럼 가늘고 배경과 유사한 객체는 실재해도 confidence가 낮다. 임계값만 높이면 실제 위험 요소를 놓친다.

반면 **탐지 프레임 수는 오탐과 실재를 잘 구분한다.** 30프레임 중 1장에서만 잡힌 객체는 오탐일 가능성이 높다.

### 중요도

전선 오탐 1건은 소형견 기준 안전성 점수를 37.5포인트, 종합 점수를 15포인트 낮춘다. 규칙 기반 산출의 재현성은 입력이 정확할 때만 의미가 있다.

> 매핑 기준은 AI 분석 정의서의 객체 코드 · 명칭 매핑을 따른다.

# Risk Classifier

## 목적

`risk_level` 을 판정한다. **YOLO는 위험도를 산출하지 않는다.**

탐지된 객체와 반려동물 그룹의 조합으로 결정한다.

```
risk_level = max(중요도 유래 등급, 객체별 최소 위험도)
```

| 객체 | 소형견 | 중·대형견 | 고양이 |
| --- | --- | --- | --- |
| 전선 | HIGH | HIGH | **HIGH** (하한 적용) |
| 계단 | MEDIUM | HIGH | LOW |
| 창문 | LOW | LOW | HIGH |
| 그 외 | SAFE | SAFE | SAFE |

전선은 감전 위험이 종에 무관하므로 최소 `HIGH` 를 보장한다. 중요도만 따르면 고양이에게 `MEDIUM`(노란색)으로 표시되어 위험을 과소 전달한다.

### 용도 제한

| 용도 | 사용 |
| --- | --- |
| 마킹 색상 결정 | ● |
| Pet Fit Score 산출 | ○ **사용하지 않음** |

`risk_level` 은 이미 그룹별 중요도를 반영한 값이다. 점수 계산식의 가중치도 같은 중요도를 사용하므로, 감점률에 반영하면 중요도가 이중 적용된다.

# Representative Frame Selection

## 목적

대표 프레임 **두 종류**를 선정한다.

| 구분 | 범위 | 용도 |
| --- | --- | --- |
| 분석 대표 프레임 | 분석당 1장 | 목록 · 썸네일 |
| 객체 대표 프레임 | 위험 객체당 1장 | 마킹 이미지 배경 |

### 분석 대표 프레임 선정 기준

우선순위 순으로 적용한다.

| 순위 | 기준 | 방향 |
| --- | --- | --- |
| 1 | 포함된 주요 객체의 종류 수 | 많을수록 |
| 2 | 해당 프레임 탐지 객체의 평균 confidence | 높을수록 |
| 3 | 프레임 번호 | 작을수록 |

### 객체 대표 프레임 선정 기준

**Object Tracking이 산출한 `frame_number` 를 그대로 사용한다.** 별도로 다시 계산하지 않는다.

| 순위 | 기준 | 방향 |
| --- | --- | --- |
| 1 | 해당 객체의 confidence | 높을수록 |
| 2 | 해당 객체의 Bounding Box 면적 | 클수록 |
| 3 | 프레임 번호 | 작을수록 |

공간을 이동하며 촬영하므로 위험 요소가 서로 다른 장면에 나타난다. 한 프레임만 사용하면 다른 장면의 위험 요소를 표시할 수 없다.

> ※ "객체 가림", "선명도" 는 측정 방법이 정의되지 않아 기준에서 제외한다. 측정 가능한 기준만 사용하며, 3순위까지 적용하면 항상 하나가 결정된다.

### 출력

- 분석 대표 프레임 1장
- 객체별 대표 프레임 (위험 객체 수만큼)

---

# Risk Object Marking

## 목적

**위험 객체마다 마킹 이미지를 개별 생성한다.**

### 생성 규칙

| 항목 | 내용 |
| --- | --- |
| 생성 대상 | risk_level이 HIGH · MEDIUM · LOW인 객체 |
| 생성 단위 | 객체 1개당 이미지 1장 |
| 배경 | 해당 객체의 객체 대표 프레임 |
| 표시 | 해당 객체의 Bounding Box 1개만 |

### 위험도별 색상

| risk_level | 표시 |
| --- | --- |
| HIGH | 빨간색 Bounding Box |
| MEDIUM | 노란색 Bounding Box |
| LOW | 초록색 Bounding Box |
| SAFE | **생성하지 않음** |

객체마다 기준 프레임이 다르므로 여러 객체를 한 이미지에 함께 그리지 않는다.

`SAFE` 까지 표시하면 화면이 Bounding Box로 가득 차 위험 요소가 묻힌다.

### 출력

- 위험 객체별 마킹 이미지 (N장)

---

# Environment Analysis

## 목적

반려동물 그룹별 생활환경을 종합 분석한다.

### 후보 모델

| 모델 | 용도 |
| --- | --- |
| GPT-4o | 환경 분석 |
| Qwen2.5-VL | 환경 분석 |

> 최종 모델은 성능평가 결과에 따라 선정한다.
> 

### 입력

**텍스트**

- animalGroup
- spaceType
- 객체 목록
- 객체 위치
- 위험 객체 정보
- occupancy_ratio
- petFitScore (Score Generator 산출 결과)

**이미지 (최대 4장)**

- 분석 대표 프레임 1장
- 위험 객체 대표 프레임 최대 3장
- Bounding Box를 그리지 않은 원본 프레임

### 출력

- 환경 분석
- 위험 요소 (DETECTED / OBSERVED 구분)
- 환경 개선 추천

### 이미지 입력이 필요한 이유

객체 탐지는 정의된 12종만 인식한다. 약병·화분·비닐봉지 등 그 외의 위험 요소는 탐지 단계에서 확인할 수 없다.

또한 위험 항목의 감점률은 탐지 여부만 사용하므로, **정리된 전선과 바닥에 엉킨 전선을 점수로 구분할 수 없다.** 이미지 입력으로 서술 단계에서 이를 보완한다.

이미지 입력이 필수이므로 **환경 분석 모델은 비전 입력을 지원해야 한다.**

> petFitScore를 입력으로 받아 점수와 서술 내용이 상충하지 않도록 생성한다.
> 
> 이미지에서 확인한 위험 요소는 `OBSERVED` 로 표기하며, 규칙 기반으로 산출된 점수에는 영향을 주지 않는다.

# Pet Fit Score Generator

## 목적

객체 탐지·추적 결과를 기반으로 **규칙 기반으로** 점수를 산출한다.

LLM/VLM은 점수를 생성하지 않는다. 점수 산출은 본 컴포넌트가 단독으로 담당한다.

### 입력

- animalGroup
- **spaceType**
- 채택된 객체 목록 (객체명)
- occupancy_ratio

`spaceType` 은 평가 항목의 적용 여부를 결정한다. 침실에서는 급식·급수 환경을, 주방에서는 휴식 공간을 평가에서 제외한다.

`risk_level` 은 입력에 포함하지 않는다. 중요도가 이중 반영된다.

좌표는 정규화되어 있으므로 해상도 정보가 필요하지 않다.

### 출력

- petFitScore (total, safety, activity, rest, environment)

### 산출 방식

| 단계 | 내용 |
| --- | --- |
| 1 | `spaceType` 으로 평가 대상 항목을 결정한다 |
| 2 | 분석 항목별 감점률 산출 |
| 3 | 반려동물 그룹별 중요도를 가중치로 적용 |
| 4 | 평가 항목별 점수 산출 (미적용 항목은 가중치 합에서 제외) |
| 5 | 비중을 적용하여 종합 점수 산출 |

> 상세 계산식과 항목별 감점 규칙은 AI 분석 정의서를 따른다.

### 특성

| 항목 | 내용 |
| --- | --- |
| 결정성 | 동일 입력에 대해 항상 동일한 점수를 산출한다. |
| 검증 | 단위 테스트로 검증 가능하다. |
| 추적성 | 항목별 감점 근거를 기록한다. |

### 평가 항목

| 항목 | 비중 |
| --- | --- |
| 안전성 | 40% |
| 활동성 | 25% |
| 휴식환경 | 20% |
| 생활환경 | 15% |

# AI 모델 선정 기준

객체 탐지 모델과 환경 분석 모델은 역할이 다르므로 기준을 분리한다.

## 객체 탐지 모델

| 평가 항목 | 비중 |
| --- | --- |
| 전체 탐지 정확도 (mAP@0.5) | 30% |
| 핵심 클래스 성능 (cable 등) | 20% |
| 추론 속도 | 20% |
| 메모리 사용량 | 15% |
| Apple MPS 최적화 | 15% |

## 환경 분석 모델

**필수 조건** : 비전 입력 지원. 이미지를 처리하지 못하면 OBSERVED 위험 요소를 생성할 수 없다.

| 평가 항목 | 비중 |
| --- | --- |
| 환경 분석 품질 | 30% |
| OBSERVED 정탐률 | 20% |
| 추천 품질 | 20% |
| 데이터 처리 위치 | 15% |
| 응답 속도 | 10% |
| 운영 비용 | 5% |

`데이터 처리 위치` 는 로컬 실행 여부를 뜻한다. 외부 API를 사용하면 생활공간 이미지가 외부로 전송된다.

> 측정 항목과 상세 기준은 AI 성능 평가서를 따른다.

# AI 설계 특징

- 영상 기반 분석 구조
- 다중 프레임 객체 탐지
- 객체 추적을 통한 중복 제거
- 탐지 신뢰 기준으로 오탐 차단
- 위험 객체별 대표 프레임 선정 및 개별 시각화
- 반려동물 그룹 맞춤 분석
- **점수와 서술의 역할 분리** — 점수는 규칙 기반으로 재현 가능하고, 서술은 생성형 AI가 담당한다
- **이미지 입력으로 탐지 대상 밖 위험 요소 보완** — 점수에는 영향을 주지 않는다
- Apple Silicon(MPS/MLX) 최적화
- AI 모델 교체가 가능한 모듈형 설계
